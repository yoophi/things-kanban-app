# Phase 0 Research: 상태 전이 태그 정규화

## 1. Canonical 진행 상태 태그

**Decision**: 새 쓰기의 canonical 태그는 사용자 요구와 동일한 `in progress`로 정한다. 기존 앱이 사용한 `status:in-progress`는 읽기 호환 대상으로 유지하며, 사용자가 명시적으로 상태를 전이할 때 canonical 태그로 정규화한다.

**Rationale**:

- 사용자에게 보이는 Things 태그가 요구한 이름과 일치한다.
- 기존 데이터의 legacy 태그를 즉시 무효화하지 않아 새 버전 전환 시 카드가 Todo로 잘못 이동하지 않는다.
- 명시적 상태 전이는 constitution이 허용하는 충돌 정규화 시점이다.

**Alternatives considered**:

- **기존 `status:in-progress` 유지**: 사용자 요구의 태그 이름과 불일치해 거부했다.
- **두 태그를 모두 추가**: 중복 권위와 완료 시 제거 범위가 커져 거부했다.
- **기존 모든 할 일을 일괄 마이그레이션**: 사용자가 전이하지 않은 데이터를 대량 변경하므로 거부했다.

## 2. Done 전이의 쓰기 순서

**Decision**: 진행 상태 태그를 먼저 제거하고 결과를 확인한 다음 실제 완료 상태로 변경하며, 마지막에 동일 ID를 다시 읽어 완료 상태와 태그 부재를 함께 검증한다.

**Rationale**:

- 사용자가 명시한 “태그 제거 후 완료” 순서를 그대로 따른다.
- 완료 후 Logbook에 이동한 항목보다 열린 항목에서 태그를 먼저 다루는 편이 안정적이다.
- 최종 재조회가 부분 성공과 외부 변경을 감지한다.

**Alternatives considered**:

- **완료 후 태그 제거**: 완료 항목 탐색과 수정이 더 불안정하고 요구 순서와 달라 거부했다.
- **한 AppleScript에서 두 변경을 실행**: 어느 단계가 실패했는지와 중간 검증을 구분하기 어려워 거부했다.
- **태그를 남기고 완료 상태만 우선**: Things 데이터에 모순된 진행 태그가 남아 거부했다.

## 3. 부분 실패 복구

**Decision**: 백엔드는 단계 실패를 성공으로 포장하거나 추측성 보상 쓰기를 하지 않는다. 오류를 반환하고 프런트엔드는 낙관적 snapshot을 복구한 뒤 전체 보드를 다시 읽어 Things의 실제 상태로 수렴한다.

**Rationale**:

- 권한이나 외부 변경으로 보상 쓰기 역시 실패할 수 있다.
- Things가 유일한 권위이므로 재조회가 가장 안전한 복구 방식이다.
- 기존 mutation의 snapshot 롤백 및 query invalidation 계약을 재사용할 수 있다.

**Alternatives considered**:

- **태그 제거 실패를 무시하고 완료**: 성공 기준을 위반해 거부했다.
- **완료 실패 시 legacy 태그를 자동 복원**: 원래 태그 집합과 외부 변경을 덮어쓸 수 있어 거부했다.
- **UI 상태 유지 후 수동 새로고침 대기**: 잘못된 성공 표시가 남아 거부했다.

## 4. 태그 보존 방식

**Decision**: 현재 태그 집합에서 canonical/legacy 진행 태그와 기존 Todo 상태 태그만 제거하고, 목표가 In Progress일 때 canonical 태그 하나를 추가한다. 비교는 앱이 정의한 상태 태그에만 적용하며 나머지 문자열은 순서와 이름을 보존한다.

**Rationale**:

- 관련 없는 사용자 태그를 변경하지 않는 constitution 요구를 만족한다.
- 중복 상태 태그와 충돌을 한 번의 명시적 전이에서 정규화한다.
- 동일 연산을 재시도해도 결과가 같은 멱등성을 얻는다.

**Alternatives considered**:

- **전체 태그 목록 재생성**: 사용자 태그 유실 위험이 있어 거부했다.
- **새 태그만 append**: legacy 및 중복 태그가 남아 거부했다.

## Resolved Unknowns

- Canonical 태그: `in progress`
- Legacy 호환 태그: `status:in-progress`
- Done 쓰기 순서: 진행 태그 제거 → 완료 처리 → 최종 재조회
- 부분 실패: 오류 반환 → UI snapshot 롤백 → 권위 상태 재조회
- 보존 범위: 상태 태그 외 모든 태그와 메타데이터 및 PARA

계획을 막는 미해결 질문은 없다.
