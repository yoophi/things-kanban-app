# Feature Specification: 완료 항목을 포함한 3열 칸반 보드

**Feature Branch**: `002-show-completed-todos`
**Created**: 2026-07-30
**Status**: Draft
**Input**: User description: "할 일을 todo, in progress, done 으로, 완료된 항목도 표시"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 세 가지 작업 상태를 한눈에 보기 (Priority: P1)

Things 사용자는 앱을 열자마자 `Todo`, `In Progress`, `Done` 세 열을 동시에 보고, 활성 할 일과 완료된 할 일이 현재 상태에 맞는 열에 배치된 모습을 확인한다.

**Why this priority**: 완료 항목까지 포함한 전체 작업 흐름을 한 화면에서 파악하는 것이 이번 기능의 핵심 가치다.

**Independent Test**: 상태 태그가 없는 활성 할 일, 진행 중 태그가 있는 활성 할 일, 최근 완료된 할 일을 각각 준비한 뒤 앱을 열어 세 열이 모두 표시되고 각 항목이 정확한 한 열에만 나타나는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 활성 및 완료 할 일이 있는 Things 환경에서, **When** 사용자가 보드를 열면, **Then** `Todo`, `In Progress`, `Done` 세 열이 별도 설정 없이 모두 표시된다.
2. **Given** 완료되지 않았고 진행 중 상태 태그가 없는 할 일이 있을 때, **When** 보드가 표시되면, **Then** 해당 할 일은 `Todo` 열에만 나타난다.
3. **Given** 완료되지 않았고 진행 중 상태 태그가 있는 할 일이 있을 때, **When** 보드가 표시되면, **Then** 해당 할 일은 `In Progress` 열에만 나타난다.
4. **Given** Things에서 최근 완료된 할 일이 있을 때, **When** 보드가 표시되면, **Then** 해당 할 일은 `Done` 열에만 나타난다.
5. **Given** 특정 열에 해당하는 할 일이 없을 때, **When** 보드가 표시되면, **Then** 해당 열은 사라지지 않고 비어 있음을 명확히 안내한다.
6. **Given** 서로 다른 프로젝트에 같은 제목의 할 일이 있을 때, **When** 보드가 표시되면, **Then** 각 카드에서 소속 프로젝트를 즉시 구별할 수 있다.

---

### User Story 2 - 완료와 완료 취소 결과를 즉시 확인하기 (Priority: P2)

사용자는 할 일을 `Done`으로 이동하거나 완료된 할 일을 다시 활성 상태로 되돌린 뒤, 결과가 Things와 보드 양쪽에 일관되게 반영되는 것을 확인한다.

**Why this priority**: 완료 항목을 단순히 보는 것뿐 아니라 세 상태 사이의 작업 흐름이 Things의 실제 완료 여부와 일치해야 신뢰할 수 있다.

**Independent Test**: 테스트 할 일을 `Todo` 또는 `In Progress`에서 `Done`으로 이동하고 다시 `Todo`와 `In Progress`로 각각 복구하여 Things의 완료 여부와 보드 열이 매번 일치하는지 검증한다.

**Acceptance Scenarios**:

1. **Given** `Todo` 또는 `In Progress` 할 일이 있을 때, **When** 사용자가 해당 할 일을 `Done`으로 이동하면, **Then** Things에서 완료 처리되고 검증 후 `Done` 열에 표시된다.
2. **Given** `Done` 할 일이 있을 때, **When** 사용자가 해당 할 일을 `Todo`로 이동하면, **Then** Things에서 완료가 취소되고 진행 중 상태 태그가 제거된 뒤 `Todo` 열에 표시된다.
3. **Given** `Done` 할 일이 있을 때, **When** 사용자가 해당 할 일을 `In Progress`로 이동하면, **Then** Things에서 완료가 취소되고 진행 중 상태가 적용된 뒤 `In Progress` 열에 표시된다.
4. **Given** 상태 변경 또는 결과 검증이 실패할 때, **When** 보드가 실패를 처리하면, **Then** 카드는 이전 열로 복원되고 원인과 재시도 방법이 표시된다.

---

### User Story 3 - 완료 항목의 최신 상태 유지하기 (Priority: P3)

사용자는 Things 앱에서 직접 완료하거나 완료 취소한 변경이 새로고침과 앱 포커스 복귀 후 세 열 보드에 반영되는 것을 확인한다.

**Why this priority**: Things가 유일한 원본이므로 앱 밖에서 발생한 완료 상태 변경도 보드에 안정적으로 수렴해야 한다.

**Independent Test**: 앱이 열린 상태에서 Things에서 직접 여러 항목을 완료·완료 취소한 다음 수동 새로고침과 포커스 복귀를 각각 실행해 정확한 열과 개수로 갱신되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 Things에서 활성 할 일을 완료했을 때, **When** 보드를 수동 새로고침하면, **Then** 해당 항목은 기존 활성 열에서 사라지고 `Done` 열에 나타난다.
2. **Given** 사용자가 Things에서 완료를 취소했을 때, **When** 앱이 다시 포커스를 얻으면, **Then** 해당 항목은 `Done`에서 사라지고 상태 태그에 맞는 활성 열에 나타난다.
3. **Given** 완료 항목이 조회 대상 기간 밖에 있을 때, **When** 보드가 갱신되면, **Then** 해당 항목은 `Done` 열에 포함되지 않고 현재 조회 기준이 사용자에게 표시된다.

---

### User Story 4 - 프로젝트별 작업 구별하기 (Priority: P4)

사용자는 세 열에 섞여 있는 카드가 어느 Things 프로젝트에 속하는지 한눈에 구별하고, 필요한 경우 특정 프로젝트의 작업만 좁혀 본다.

**Why this priority**: 여러 프로젝트에서 비슷한 제목의 할 일을 운영할 때 소속 정보가 분명해야 잘못된 작업을 완료하거나 이동하는 실수를 방지할 수 있다.

**Independent Test**: 같은 제목을 포함한 할 일을 서로 다른 프로젝트, 프로젝트 없는 Area 직속 위치 및 소속 없음 상태로 준비한 뒤 카드의 소속 표기와 프로젝트 필터 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 프로젝트에 속한 할 일이 있을 때, **When** 카드가 표시되면, **Then** 프로젝트 이름이 카드 제목과 구별되는 일관된 위치에 표시된다.
2. **Given** 프로젝트가 Area에 속해 있을 때, **When** 카드가 표시되면, **Then** 프로젝트 이름을 우선 표시하면서 상위 Area도 함께 구별할 수 있다.
3. **Given** 프로젝트 없이 Area에 직접 속한 할 일이 있을 때, **When** 카드가 표시되면, **Then** 프로젝트가 있는 것처럼 오인되지 않는 방식으로 Area 소속이 표시된다.
4. **Given** 프로젝트와 Area 소속이 모두 없는 할 일이 있을 때, **When** 카드가 표시되면, **Then** 소속 없음이 다른 프로젝트 이름과 혼동되지 않게 표현된다.
5. **Given** 여러 프로젝트의 할 일이 세 열에 표시될 때, **When** 사용자가 특정 프로젝트를 선택하면, **Then** 세 열 모두에서 해당 프로젝트의 할 일만 남고 각 열의 개수가 갱신된다.

---

### User Story 5 - 사이드바에서 Area와 Project 탐색하기 (Priority: P5)

사용자는 사이드바에서 Things의 Area와 Project 구조를 살펴보고 하나를 선택해, 메인 영역에서 선택 범위에 해당하는 할 일만 `Todo`, `In Progress`, `Done` 칸반으로 확인한다.

**Why this priority**: 작업 상태와 프로젝트 소속을 동시에 이해하려면 PARA 구조를 탐색하는 영역과 실제 작업 흐름을 보는 영역이 명확히 분리되어야 한다.

**Independent Test**: 여러 Area, 각 Area의 하위 Project, Area 직속 할 일과 독립 Project를 준비한 뒤 사이드바 항목을 차례로 선택해 메인 칸반의 제목, 카드, 열별 개수가 선택 범위와 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** Things에 활성 Area와 Project가 있을 때, **When** 사용자가 앱을 열면, **Then** 사이드바에 전체 보기와 Area 및 Project 탐색 항목이 표시된다.
2. **Given** Project가 Area에 속해 있을 때, **When** 사이드바가 표시되면, **Then** Project는 해당 Area와의 관계를 이해할 수 있는 계층 또는 그룹으로 표시된다.
3. **Given** 사용자가 특정 Project를 선택했을 때, **When** 메인 영역이 갱신되면, **Then** 해당 Project의 할 일만 세 상태 열에 표시되고 선택한 Project 이름이 메인 영역의 현재 범위로 표시된다.
4. **Given** 사용자가 특정 Area를 선택했을 때, **When** 메인 영역이 갱신되면, **Then** 해당 Area의 직속 할 일과 그 Area에 속한 Project의 할 일이 세 상태 열에 표시된다.
5. **Given** 사용자가 전체 보기를 선택했을 때, **When** 메인 영역이 갱신되면, **Then** 지원 범위의 모든 할 일이 세 상태 열에 표시된다.
6. **Given** 선택한 Area 또는 Project에 할 일이 없을 때, **When** 메인 영역이 표시되면, **Then** 사이드바 선택은 유지되고 세 열 각각의 빈 상태가 표시된다.
7. **Given** 현재 선택된 Area 또는 Project가 Things에서 삭제되거나 비활성화되었을 때, **When** 보드가 새로고침되면, **Then** 전체 보기로 안전하게 전환되고 변경 사실을 사용자에게 알린다.

### Edge Cases

- 완료일이 없는 항목이 완료 상태로 반환되면 `Done`으로 분류하되 기간 필터 판단이 불가능함을 안전하게 처리한다.
- 동일한 활성 할 일에 `status:todo`와 `status:in-progress`가 함께 있으면 충돌 상태를 표시하고, 사용자가 명시적으로 이동하기 전에는 원본 태그를 변경하지 않는다.
- 완료된 할 일에 상태 태그가 남아 있어도 Things의 실제 완료 상태를 우선해 `Done`으로 한 번만 표시한다.
- 새로고침 도중 외부 변경과 앱 상태 전이가 겹치면 Things에서 마지막으로 확인한 상태를 최종 결과로 사용한다.
- 완료 항목이 많아도 정해진 최근 기간만 조회해 보드가 불필요하게 느려지지 않아야 한다.
- 자동화 권한이 없거나 Things를 사용할 수 없으면 빈 세 열을 정상 데이터처럼 표시하지 않고 원인과 해결 방법을 안내한다.
- 검색 또는 필터 결과가 한 열에서만 없을 때도 다른 열과 빈 열의 구조는 유지한다.
- 이름이 같은 프로젝트가 존재하면 이름만으로 필터 대상을 결정하지 않고 각 프로젝트를 서로 다른 선택 항목으로 구별한다.
- 프로젝트나 Area 이름이 길어도 카드의 상태와 제목을 가리지 않으며 전체 소속 정보를 확인할 수 있어야 한다.
- 프로젝트 이름이 변경되면 새로고침 후 모든 관련 카드와 필터 항목에 최신 이름이 반영되어야 한다.
- Area에 속하지 않은 독립 Project도 사이드바에서 누락되지 않고 별도 그룹으로 구별되어야 한다.
- 이름이 같은 Area 또는 Project가 있어도 사이드바 선택과 메인 결과는 Things 식별자를 기준으로 정확히 유지되어야 한다.
- 사이드바에 표시할 Area와 Project가 많아도 현재 선택 항목을 찾고 키보드로 이동할 수 있어야 한다.
- 사이드바가 좁은 창에서 메인 칸반을 지나치게 가리면 접거나 다시 펼칠 수 있어야 하며, 선택한 범위는 유지되어야 한다.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: 시스템은 기본 보드에 `Todo`, `In Progress`, `Done` 세 열을 항상 표시해야 한다.
- **FR-002**: 시스템은 완료되지 않았고 `status:in-progress` 태그가 없는 할 일을 `Todo`로 분류해야 한다.
- **FR-003**: 시스템은 완료되지 않았고 `status:in-progress` 태그가 있는 할 일을 `In Progress`로 분류해야 한다.
- **FR-004**: 시스템은 상태 태그와 관계없이 Things에서 실제 완료된 할 일을 `Done`으로 분류해야 한다.
- **FR-005**: 각 할 일은 동시에 둘 이상의 열에 표시되지 않아야 한다.
- **FR-006**: 시스템은 기본적으로 최근 30일 이내의 완료 항목을 조회해 `Done` 열에 표시해야 한다.
- **FR-007**: `Done` 열 제목 또는 보드 내 안내는 현재 완료 항목 조회 기간이 최근 30일임을 알려야 한다.
- **FR-008**: 각 열은 현재 검색·필터 조건에 해당하는 할 일 개수를 표시해야 한다.
- **FR-009**: 시스템은 할 일을 `Done`으로 이동하면 Things의 실제 완료 상태를 변경하고, 완료된 할 일을 활성 열로 이동하면 완료를 취소해야 한다.
- **FR-010**: 완료 취소 후 `Todo`로 이동할 때 진행 중 상태 태그를 제거하고, `In Progress`로 이동할 때 진행 중 상태 태그를 적용해야 한다.
- **FR-011**: 모든 상태 변경은 Things에서 결과를 다시 확인한 후에만 성공으로 확정해야 한다.
- **FR-012**: 상태 변경이나 검증 실패 시 시스템은 카드를 이전 열로 복원하고 재시도 가능한 오류 안내를 제공해야 한다.
- **FR-013**: 시스템은 앱 시작, 수동 새로고침 및 앱 포커스 복귀 시 활성 항목과 최근 완료 항목을 함께 갱신해야 한다.
- **FR-014**: 검색, 프로젝트, Area 및 태그 필터는 세 열 전체에 동일하게 적용되어야 하며 열별 개수도 함께 갱신되어야 한다.
- **FR-015**: 완료 항목이 없거나 필터 결과가 없어도 `Done` 열을 숨기지 않고 빈 상태를 표시해야 한다.
- **FR-016**: 시스템은 취소된 할 일을 세 열 어디에도 표시하지 않아야 한다.
- **FR-017**: 프로젝트에 속한 각 카드는 프로젝트 이름을 제목 및 상태 정보와 시각적으로 구분해 표시해야 한다.
- **FR-018**: 프로젝트가 상위 Area에 속한 경우 카드는 프로젝트와 Area의 관계를 함께 식별할 수 있게 표시해야 한다.
- **FR-019**: 프로젝트 없이 Area에 직접 속한 카드와 아무 소속이 없는 카드는 프로젝트 소속 카드와 혼동되지 않게 구분해야 한다.
- **FR-020**: 프로젝트 필터는 표시 이름이 아니라 Things의 프로젝트 식별자를 기준으로 서로 다른 프로젝트를 구분해야 한다.
- **FR-021**: 사용자가 프로젝트 필터를 적용하면 해당 조건은 `Todo`, `In Progress`, `Done` 세 열에 동일하게 적용되어야 한다.
- **FR-022**: 새로고침 후 프로젝트 및 Area 이름 변경 사항은 관련 카드와 필터 선택 항목에 함께 반영되어야 한다.
- **FR-023**: 앱은 사이드바와 메인 칸반 영역을 명확히 구분된 기본 화면 구조로 제공해야 한다.
- **FR-024**: 사이드바는 전체 보기, 활성 Area 및 활성 Project를 표시해야 한다.
- **FR-025**: 사이드바는 각 Project가 속한 Area를 이해할 수 있도록 Area와 Project의 관계를 계층 또는 그룹으로 표현해야 한다.
- **FR-026**: Area에 속하지 않은 Project는 사이드바의 별도 구분 영역에서 선택 가능해야 한다.
- **FR-027**: 사용자가 Project를 선택하면 메인 칸반은 해당 Project 소속 할 일만 표시해야 한다.
- **FR-028**: 사용자가 Area를 선택하면 메인 칸반은 해당 Area 직속 할 일과 Area에 속한 모든 Project의 할 일을 표시해야 한다.
- **FR-029**: 사용자가 전체 보기를 선택하면 메인 칸반은 현재 지원되는 모든 할 일을 표시해야 한다.
- **FR-030**: 메인 영역은 현재 선택된 전체 보기, Area 또는 Project의 이름과 종류를 표시해야 한다.
- **FR-031**: 사이드바 범위 변경은 `Todo`, `In Progress`, `Done` 세 열, 열별 개수 및 다른 검색·태그 조건에 일관되게 적용되어야 한다.
- **FR-032**: 선택한 Area 또는 Project에 결과가 없어도 메인 영역은 세 열을 유지하고 범위에 맞는 빈 상태를 표시해야 한다.
- **FR-033**: 새로고침 후 현재 선택 대상이 더 이상 존재하지 않으면 전체 보기로 전환하고 사용자에게 이유를 알려야 한다.
- **FR-034**: 사이드바는 접기와 펼치기를 지원해야 하며, 표시 상태가 바뀌어도 현재 선택 범위는 유지되어야 한다.
- **FR-035**: 사이드바의 Area와 Project는 이름이 중복되더라도 Things 식별자를 기준으로 독립적으로 선택되어야 한다.

### Things Integration and Safety _(mandatory when Things data is read or written)_

- **TI-001**: 활성 및 완료 할 일 조회와 변경 후 확인은 읽기 작업이며, 완료·완료 취소 및 상태 태그 변경은 쓰기 작업으로 구분해야 한다.
- **TI-002**: 완료, 완료 취소 및 상태 태그 쓰기는 지원되는 AppleScript 또는 Things URL 동작만 사용해야 하며 Things 데이터 저장소에 직접 쓰면 안 된다.
- **TI-003**: 각 상태 변경은 대상 Things 식별자, 이전 상태와 목표 상태를 포함하고, 쓰기 후 재조회 검증에 실패하면 보드 표시를 이전 상태로 복원해야 한다.
- **TI-004**: 자동화 권한 거부, Things 사용 불가, 충돌 상태 태그 및 외부 완료 상태 변경을 서로 구분해 처리해야 한다.
- **TI-005**: 상태 변경은 완료 여부와 알려진 상태 태그만 수정하고 관련 없는 태그, 일정, 프로젝트, Area 및 기타 메타데이터를 보존해야 한다.
- **TI-006**: 완료 상태는 Things의 실제 완료 여부만을 권위로 사용하며 별도의 완료 태그나 독자적인 영구 상태를 만들면 안 된다.
- **TI-007**: 프로젝트와 Area 소속 및 이름은 Things에서 읽은 최신 정보를 기준으로 하며 앱이 별도의 프로젝트 분류를 만들면 안 된다.
- **TI-008**: 사이드바의 Area·Project 목록과 계층 관계는 Things에서 조회한 최신 구조를 반영해야 하며, 사이드바 선택은 Things 데이터를 변경하지 않는 읽기 전용 동작이어야 한다.

### Accessibility Requirements _(mandatory for interactive UI)_

- **AR-001**: 세 열 사이의 모든 드래그 앤 드롭 상태 변경은 키보드로도 동일하게 실행할 수 있어야 한다.
- **AR-002**: 로딩, 빈 열, 상태 변경 중, 성공 및 실패는 색상에만 의존하지 않고 인지 가능해야 한다.
- **AR-003**: 각 카드의 현재 열, 이동 가능한 목표 상태와 이동 결과가 보조 기술 사용자에게 전달되어야 한다.
- **AR-004**: `Todo`, `In Progress`, `Done` 열은 의미 있는 제목과 개수를 가져야 하며 키보드 탐색에서 구분 가능해야 한다.
- **AR-005**: 프로젝트와 Area 구분은 색상에만 의존하지 않고 텍스트 또는 동등한 접근 가능한 이름으로 전달되어야 한다.
- **AR-006**: 사이드바의 전체 보기, Area와 Project 항목은 키보드만으로 탐색하고 선택할 수 있어야 하며 현재 선택 상태가 보조 기술에 전달되어야 한다.
- **AR-007**: 사이드바와 메인 칸반은 의미 있는 영역 이름을 가져야 하며 사용자가 두 영역 사이를 효율적으로 이동할 수 있어야 한다.
- **AR-008**: 사이드바 접기·펼치기 조작은 키보드로 실행 가능하고 현재 상태를 전달해야 한다.

### Key Entities _(include if feature involves data)_

- **Todo**: Things의 할 일로, 식별자, 제목, 실제 완료 상태, 완료일, 상태 태그, 프로젝트 또는 Area 및 기타 태그를 가진다.
- **Kanban Status**: 보드에서 파생한 `Todo`, `In Progress`, `Done` 중 하나의 상태다.
- **Board Column**: 하나의 칸반 상태와 해당 상태로 분류된 할 일 목록 및 표시 개수를 나타낸다.
- **Project Context**: 카드가 속한 Things 프로젝트와 선택적인 상위 Area를 나타내며 프로젝트 식별자와 표시 이름을 포함한다.
- **Board Scope**: 사이드바에서 선택한 전체 보기, Area 또는 Project로, 메인 칸반에 포함할 할 일 범위를 결정한다.
- **Sidebar Node**: 선택 가능한 Area 또는 Project 항목으로, Things 식별자, 표시 이름, 종류 및 선택적인 부모 Area 관계를 가진다.
- **Completion Window**: `Done` 열에 포함할 완료 항목의 최근 조회 기간으로, 기본값은 30일이다.
- **Status Transition**: 한 할 일의 이전 상태, 목표 상태, Things 쓰기와 사후 검증 결과를 포함한다.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 사용자는 앱을 연 뒤 5초 이내에 `Todo`, `In Progress`, `Done` 세 열과 각 열의 항목 개수 또는 조치 가능한 연결 오류를 확인할 수 있다.
- **SC-002**: 대표 활성·완료 데이터 집합에서 100%의 할 일이 상태 규칙에 맞는 정확히 한 열에만 표시된다.
- **SC-003**: 최근 30일 이내 완료된 대표 항목의 100%가 `Done` 열에 표시되고 기간 밖 항목은 표시되지 않는다.
- **SC-004**: 정상 환경에서 완료 또는 완료 취소 요청의 100%가 3초 이내에 검증된 새 열 또는 명확한 실패·복구 결과를 제공한다.
- **SC-005**: 실패가 주입된 상태 전이의 100%가 이전 열로 복원되며 관련 없는 Things 데이터가 변경되지 않는다.
- **SC-006**: 키보드 전용 검증에서 세 열 사이의 모든 지원 상태 전이를 완료할 수 있고 이동 결과를 비시각적으로 확인할 수 있다.
- **SC-007**: 외부에서 완료·완료 취소한 대표 항목의 100%가 수동 새로고침 또는 포커스 복귀 후 5초 이내에 정확한 열로 갱신된다.
- **SC-008**: 사용성 검증 참가자의 90% 이상이 별도 안내 없이 현재 작업, 진행 중 작업과 최근 완료 작업을 구분하고 완료 항목을 찾을 수 있다.
- **SC-009**: 서로 다른 프로젝트에 같은 제목의 할 일이 있는 대표 시나리오에서 사용자의 100%가 각 카드의 프로젝트 소속을 정확히 구별할 수 있다.
- **SC-010**: 프로젝트 필터 검증에서 세 열에 표시되는 카드의 100%가 선택한 프로젝트에 속하며 열별 개수가 필터 결과와 일치한다.
- **SC-011**: 대표 Area를 선택했을 때 해당 Area 직속 및 하위 Project 할 일의 100%가 포함되고 다른 Area의 할 일은 표시되지 않는다.
- **SC-012**: 대표 Project를 선택했을 때 메인 칸반 카드의 100%가 선택한 Project에 속하며 세 열의 합계가 결과 수와 일치한다.
- **SC-013**: 사용성 검증 참가자의 90% 이상이 10초 이내에 사이드바에서 지정된 Area 또는 Project를 찾아 선택하고 메인 칸반의 현재 범위를 확인할 수 있다.
- **SC-014**: 키보드 전용 검증에서 전체 보기, Area 및 Project 선택과 사이드바 접기·펼치기 시나리오의 100%를 완료할 수 있다.

## Assumptions

- 세 열은 선택적으로 표시하는 기능이 아니라 앱의 기본 보드 구조로 항상 보인다.
- `Done`은 상태 태그가 아니라 Things의 실제 완료 상태를 의미한다.
- 완료 항목은 성능과 정보 밀도를 고려해 기본적으로 최근 30일 범위만 표시한다.
- `Todo`는 기존 도메인 상태명 `todo`, 화면 레이블 `Todo`를 의미하며 `In Progress`는 `status:in-progress` 태그로 표현한다.
- `status:todo` 태그는 허용하지만 필수는 아니며, 상태 태그가 없는 열린 할 일도 `Todo`로 간주한다.
- 완료 기간 사용자 설정 확대는 이번 기능 범위에 포함하지 않으며 후속 기능으로 다룰 수 있다.
- 기존 검색, 프로젝트·Area·태그 필터, 새로고침, Things에서 열기와 안전한 상태 전이 기능은 그대로 유지한다.
- 카드에서는 프로젝트 이름을 우선적인 소속 정보로 사용하고, 프로젝트가 없을 때 Area 또는 소속 없음 상태를 표시한다.
- 사이드바의 기본 선택은 전체 보기이며, 사이드바 선택은 앱의 표시 범위만 변경하고 Things 데이터를 수정하지 않는다.
- Area 선택은 그 Area의 직속 할 일뿐 아니라 해당 Area에 속한 Project의 할 일까지 포함한다.
- 기존 상단 프로젝트·Area 선택 컨트롤은 사이드바 탐색으로 대체하거나 중복되지 않게 정리하되, 제목 검색과 태그 등 보완 필터는 메인 영역에서 유지할 수 있다.
